Complete help

What is OopsMCP?

A role-based MCP toolbox with 500 practical capabilities, 25 roles, dedicated tool UIs, an MCP endpoint, memory/content support and an embedded OopsFlow integration.

What gets deployed?

Your fork contains the application source. Vercel builds that source into your private deployment. You control the repository, deployment and environment variables.

Supabase setup

Supabase is optional for the basic capability registry but required for persistent auth, memory and content storage.

  1. Create a Supabase project.
  2. Run supabase/schema.sql in the SQL editor.
  3. In Vercel, add NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY.
  4. Redeploy if Vercel does not automatically rebuild after the environment variables are added.

Workflow and pipeline execution layer that consumes OopsMCP capabilities.

FAQ

Why fork first?

Your GitHub repository remains the source you own and customize. Vercel deploys your copy instead of making the upstream OopsMCP repository your source of truth.

Can I update later?

Yes. Pull upstream changes into your fork when you want them, review them, and redeploy from your fork.

Do I need Supabase?

Not for the basic static capability experience. Add it when you need persistent authentication, memory or content storage.

Where is the MCP URL?

Use the deployed Vercel URL followed by /mcp. Register that endpoint in an MCP-capable client.
